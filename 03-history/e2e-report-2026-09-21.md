## 2. BUG-12 — 500 intermiten pada `/api/boards/:id`

**Prioritas: P1.** Pengguna login → halaman board kadang error, refresh lalu berhasil.

### Gejala terukur

Dua puluh percobaan berurutan pada `GET /api/boards/:id` (request satu per satu,
**tanpa konkurensi**):

| Hasil | Jumlah | Waktu respons |
|---|---|---|
| 200 | 17 | median **1.2 s** |
| 500 | 3 | **24.8 s, 37.2 s, 74.6 s** |

Simulasi beban nyata (20 × "board detail + boards list", pola yang dilakukan dashboard):

- **1/20 load gagal** (`GET /api/boards` → 500 setelah **29.8 s**)
- **8/20 load memakan > 3 detik**

### Bukti dari `wrangler tail` (produksi)

Tiga query berbeda gagal, di request berbeda:

```
(error) Unhandled error: Error: Failed query:
  select "id","task_id","title","is_done","position","created_at" from "subtasks"
  where false order by "subtasks"."position" asc
params:                                   ← perhatikan: kosong

(error) Unhandled error: Error: Failed query:
  select ... from "boards" where ("boards"."id" = $1 and "boards"."user_id" = $2) limit $3
params: fe13e885-f5ed-411e-b297-b7f542fe1629,9fe36a68-...,1

(ERROR) Better Auth: INTERNAL_SERVER_ERROR
  Error: Failed query: select ... from "session" where "session"."token" = $1
  Unhandled error: APIError: Failed to get session
```

`wallTime` request yang gagal: **39 619 ms** dan **85 389 ms**.
Request normal: **1 470–3 264 ms**.

### Akar masalah

Bukan bug SQL. Query-nya valid (params terisi, SQL benar) dan board yang sama
**berhasil pada request berikutnya**. Yang terjadi: **koneksi Neon menggantung
belasan sampai puluhan detik, lalu melempar error.** Request lambat *adalah*
request yang gagal — bukan dua populasi terpisah.

Bukti bahwa ini **bukan** concurrency aplikasi:

| Pola | Kegagalan |
|---|---|
| 12 request **berurutan** (satu per satu) | **1/12 gagal** |
| 15 request **5 paralel** | **0/15 gagal** |

Kalau penyebabnya concurrency di aplikasi, polanya akan terbalik. Yang gagal juga
query acak — termasuk `subtasks` dengan `where false`, yaitu query paling murah
yang bisa dijalankan. Jadi beban bukan faktor.

`drizzle-orm/neon-http` melakukan **satu HTTP fetch per query**, dan
`GET /api/boards/:id` menjalankan **5 query** (board, statuses, tasks, labels,
subtasks, taskLabels). Tidak ada retry/timeout pada jalur itu — satu fetch yang
menggantung menjatuhkan seluruh route menjadi 500 generik.

Indikasi kuat penyebab ada di sisi **connection pooling Neon** (project
`cold-brook-93438292`, free plan, endpoint `-pooler`), bukan di aplikasi.

### Bukti tambahan (edge-level)

Respons 500 yang lambat **tidak punya header `cf-ray`**, sementara semua respons
200 punya. Artinya request itu tidak selesai di edge Cloudflare sebagai respons
normal — konsisten dengan "menggantung sampai mati", bukan sekadar error aplikasi.

### Catatan: `WARN` Better Auth — rate limiting buta IP

Muncul di setiap request:

```
WARN [Better Auth]: Rate limiting could not determine a client IP and is falling
back to a single shared per-path bucket. Ensure your runtime forwards a trusted
client IP header, then set `advanced.ipAddress.ipAddressHeaders` or
`advanced.ipAddress.trustedProxies`.
```

Konsekuensi nyata (bukan kosmetik): **semua pengguna berbagi satu bucket
per-path.** Satu klien yang agresif bisa membuat pengguna lain kena rate limit,
dan rate limiting per-IP efektif tidak berjalan. Header yang tersedia di Worker
adalah `cf-connecting-ip`, jadi perbaikannya adalah mendeklarasikannya sebagai
trusted header.

   BUG-9 yang sebenarnya. Test yang tidak memeriksa klaimnya tidak menjaga klaimnya.

## 5. Provisioning fixture — catatan teknis

Akun E2E dibuat langsung di DB produksi mengikuti pola `src/db/seed.ts`.
Dua jebakan yang ditemukan (keduanya menyebabkan login 401 palsu):

1. **Skema `public`, bukan `neon_auth`.** Database punya *dua* set tabel
   (`public` + `neon_auth`); `neon_auth` adalah sisa Managed Better Auth dan tidak
   dipakai. Kolom `public` memakai **snake_case**: `email_verified`,
   `must_change_password`, `created_at`, `updated_at`, `user_id`, `account_id`,
   `provider_id` — bukan camelCase seperti `neon_auth` dan bukan seperti yang
   ditulis `seed.ts`. `seed.ts` lewat `internalAdapter` jadi tidak terpengaruh.
2. **Salt harus string hex, bukan Buffer.** Hash harus dibuat oleh
   `@better-auth/utils/password`'s `hashPassword` (scrypt N=16384, r=16, p=1,
   dkLen=64, salt = **16 byte acak sebagai hex string**). Mencoba meniru dengan
   `crypto.scryptSync(pwd, saltBuffer, ...)` menghasilkan hash yang **tidak cocok**
   → 401. Pakai `import { hashPassword } from '@better-auth/utils/password'`
   langsung; jangan meniru.

Akun `e2e-*@flowboard.test` dihapus setelah pengujian.
